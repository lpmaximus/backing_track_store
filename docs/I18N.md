# Internacionalização (pt-BR / en)

Decisão completa em `2-DOCS/ADR-ARCHITECTURAL DECISION RECORD/ADR-BTS-006.docx`.
Este arquivo é o guia prático de quem vai mexer no código.

## Como funciona

- Biblioteca: **next-intl v4** sobre o App Router.
- Páginas ficam em `app/[locale]/`. **`/api` e `/admin` estão fora** — o admin segue só em português.
- Português é o idioma padrão e **não tem prefixo**: `backingtrack.store/planos` continua igual.
  Inglês fica em `/en` com slug traduzido: `backingtrack.store/en/pricing`.

## Arquivos

| Arquivo | Papel |
|---|---|
| `src/i18n/routing.ts` | Locales, idioma padrão e **mapa de slugs por idioma** |
| `src/i18n/navigation.ts` | `Link`, `useRouter`, `usePathname`, `redirect`, `getPathname` cientes de idioma |
| `src/i18n/request.ts` | Carrega `messages/{locale}.json` por request |
| `src/i18n/geo.ts` | Regra de idioma por país (fora da lusofonia → inglês) |
| `proxy.ts` | Aplica geo + auth + middleware do next-intl |
| `messages/pt.json`, `messages/en.json` | Catálogo de textos (as duas devem ter as mesmas chaves) |
| `src/lib/pricingIntl.ts` | Preço por moeda — **fonte única**, home e /planos leem daqui |

## Regras ao escrever código

1. **Nunca** importe `Link` de `next/link` dentro de `app/[locale]/`. Use:
   ```ts
   import { Link } from "@/src/i18n/navigation";
   ```
   O mesmo vale para `useRouter` e `usePathname`.

2. Rota nova = entrada nova em `pathnames` (`src/i18n/routing.ts`). O TypeScript
   recusa um `href` que não esteja no mapa, então o erro aparece no build.

3. `router.push` para rota dinâmica usa a forma tipada:
   ```ts
   router.push({ pathname: "/song/[slug]", params: { slug } });
   ```

4. Texto novo entra **nos dois** arquivos de mensagem. Para conferir se não
   ficou chave órfã:
   ```bash
   node -e "const a=require('./messages/pt.json'),b=require('./messages/en.json');
   const k=o=>Object.entries(o).flatMap(([x,v])=>typeof v==='object'&&!Array.isArray(v)?k(v).map(s=>x+'.'+s):[x]);
   const A=k(a),B=k(b);
   console.log('só pt:',A.filter(x=>!B.includes(x)));
   console.log('só en:',B.filter(x=>!A.includes(x)));"
   ```

5. Preço **nunca** hardcoded em componente. Use `getPrice(plan, cycle, locale)`.

## Ordem de precedência do idioma

1. Prefixo na URL (`/en/...`)
2. Cookie `NEXT_LOCALE` (escolha manual no seletor do rodapé)
3. País do IP (`x-vercel-ip-country`): BR, PT, AO, MZ, CV, GW, ST, TL, GQ → pt; resto → en
4. `Accept-Language`
5. Português

O redirect geográfico sai com `Cache-Control: no-store` — sem isso a CDN
serviria para todo mundo o idioma do primeiro visitante.

## Testando localmente

O header de país não existe em `localhost`, então cai no `Accept-Language`.
Para simular:

```bash
curl -I -H "x-vercel-ip-country: US" http://localhost:3000/     # espera 307 → /en
curl -I -H "x-vercel-ip-country: BR" http://localhost:3000/     # espera 200
curl -I http://localhost:3000/en/pricing                        # sempre inglês
```

Em produção, testar com VPN em janela anônima (o cookie gruda).
