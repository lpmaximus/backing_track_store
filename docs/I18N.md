# Internacionalização (pt-BR / en / es)

Decisão completa em `2-DOCS/ADR-ARCHITECTURAL DECISION RECORD/ADR-BTS-006.docx`.
Este arquivo é o guia prático de quem vai mexer no código.

## Como funciona

- Biblioteca: **next-intl v4** sobre o App Router.
- Páginas ficam em `app/[locale]/`. **`/api` e `/admin` estão fora** — o admin segue só em português.
- Português é o idioma padrão e **não tem prefixo**: `backingtrack.store/planos` continua igual.
  Inglês fica em `/en` com slug traduzido: `backingtrack.store/en/pricing`.
  Espanhol fica em `/es` com slug traduzido: `backingtrack.store/es/precios`.
- **Espanhol nunca é escolhido automaticamente.** Regra de produto: fora do
  Brasil (e da lusofonia) o site abre em inglês. O espanhol só entra quando o
  visitante escolhe no combo de idioma (header no desktop, menu ☰ no celular,
  rodapé), e a escolha fica gravada no cookie `NEXT_LOCALE`.

## Regras ao escrever código

1. **Nunca** importe `Link` de `next/link` dentro de `app/[locale]/`. Use:
   ```ts
   import { Link } from "@/src/i18n/navigation";
   ```
   O mesmo vale para `useRouter` e `usePathname`.

2. Rota nova = entrada nova em `pathnames` (`src/i18n/routing.ts`). O TypeScript
   recusa um `href` que não esteja no mapa, então o erro aparece no build.

3. `router.push` para rota dinâmica usa a forma tipada:
   ```ts
   router.push({ pathname: "/song/[slug]", params: { slug } });
   ```

4. Texto novo entra **nos três** arquivos de mensagem. Para conferir se não
   ficou chave órfã:
   ```bash
   node -e "const k=o=>Object.entries(o).flatMap(([x,v])=>typeof v==='object'&&!Array.isArray(v)?k(v).map(s=>x+'.'+s):[x]);
   const P=k(require('./messages/pt.json'));
   for (const l of ['en','es']) { const B=k(require('./messages/'+l+'.json'));
     console.log(l,'faltando:',P.filter(x=>!B.includes(x)),'sobrando:',B.filter(x=>!P.includes(x))); }"
   ```

5. Preço **nunca** hardcoded em componente. Use `getPrice(plan, cycle, locale)`.

6. Nunca compare `locale === "en"` para decidir entre "pt" e "o resto": com três
   idiomas isso manda o espanhol para o português. Use `locale === "pt" ? … : …`
   ou, para datas, `htmlLang[locale]` (`src/i18n/routing.ts`).

## Ordem de precedência do idioma

1. Prefixo na URL (`/en/...`, `/es/...`)
2. Cookie `NEXT_LOCALE` (escolha manual no combo de idioma — único caminho para o espanhol)
3. País do IP (`x-vercel-ip-country`): BR, PT, AO, MZ, CV, GW, ST, TL, GQ → pt; resto → en
4. `Accept-Language`
5. Português

O redirect geográfico sai com `Cache-Control: no-store` — sem isso a CDN
serviria para todo mundo o idioma do primeiro visitante.

## Testando localmente

O header de país não existe em `localhost`, então cai no `Accept-Language`.
Para simular:

```bash
curl -I -H "x-vercel-ip-country: US" http://localhost:3000/     # espera 307 → /en
curl -I -H "x-vercel-ip-country: BR" http://localhost:3000/     # espera 200
curl -I http://localhost:3000/en/pricing                        # sempre inglês
```

Em produção, testar com VPN em janela anônima (o cookie gruda).

## O que ainda falta

- `/termos`, `/privacidade`, `/cookies` em espanhol: hoje `/es` mostra a versão
  em inglês (texto jurídico pede revisão, não tradução direta).
- E-mails de ciclo de vida (`src/lib/lifecycle.ts`) só têm pt/en — quem usa o
  site em espanhol recebe em inglês. Os e-mails de senha e link de acesso
  (`src/lib/authEmails.ts`) já têm espanhol.
- Checkout internacional: o Asaas é só Brasil. Ver ADR-BTS-006 §3.3.
- Notificações gravadas no banco continuam em português.
